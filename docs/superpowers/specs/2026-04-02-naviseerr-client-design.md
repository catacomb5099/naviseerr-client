# Naviseerr Client - Design Document

**Date:** 2026-04-02  
**Project:** Naviseerr Music Search & Download Client  
**Status:** Approved

## Overview

Naviseerr Client is a React-based web application for searching and downloading music. It connects to a Spring REST API backend that provides search capabilities across songs, albums, and artists, and triggers asynchronous downloads.

### Key Requirements
- Minimal frontend implementation (client-only, no backend coupling)
- Search interface with filterable results (Songs, Albums, Artists)
- Download functionality with 30-second cooldown per song
- Spotify/YouTube Music-inspired aesthetic
- Docker deployment on local network
- Maintainable by a backend engineer with minimal frontend experience

## 1. Tech Stack

### Core Dependencies
- **React 18.3.1** - UI framework
- **TypeScript 5.5.3** - Type safety
- **Vite 5.4.0** - Build tool and dev server
- **Tailwind CSS 3.4.1** - Utility-first styling
- **shadcn/ui** - Pre-built component library (Button, Input, Card, Tabs, Badge)

### Rationale
- **Vite**: Fast dev server with zero configuration
- **Tailwind + shadcn/ui**: Professional Spotify-like aesthetics without complex CSS
- **No state management libraries**: React useState is sufficient for this scope
- **Native fetch API**: No need for axios or other HTTP libraries

## 3. API Layer

### Data Types

```typescript
export interface Song {
  id: string
  iconURL: string
  streamURL: string
  name: string
  artists: string[]        // List of artist IDs
  albumId: string
  year: number
}

export interface Album {
  id: string
  iconURL: string
  name: string
  artists: string[]        // List of artist IDs
  year: number
}

export interface Artist {
  id: string
  iconUrl: string
  name: string
}

export interface SearchResponse {
  songs: Song[]
  albums: Album[]
  artists: Artist[]
}
```

### API Endpoints

| Function | HTTP Method | Endpoint | Returns | Status |
|----------|-------------|----------|---------|--------|
| `search(query: string)` | GET | `/search/{query}` | `SearchResponse` | Active |
| `searchSongs(query: string)` | GET | `/search/{query}/songs` | `Song[]` | Mock (future) |
| `searchAlbums(query: string)` | GET | `/search/{query}/albums` | `Album[]` | Mock (future) |
| `searchArtists(query: string)` | GET | `/search/{query}/artists` | `Artist[]` | Mock (future) |
| `download(songId: string)` | GET | `/download/{songId}` | `void` | Active |

### API Client Configuration
- **Base URL**: From environment variable `VITE_API_URL` (default: `http://localhost:8080`)
- **Error Handling**: 
  - Throw on non-2xx responses
  - Display user-friendly error messages
  - Network errors show alert/toast

### Mock Implementation
- `searchSongs`, `searchAlbums`, `searchArtists` return empty arrays until backend endpoints are ready
- Allows frontend development to proceed independently

### Filter Pills Behavior
- Four pills: **All**, **Songs**, **Albums**, **Artists**
- Only one pill selected at any time (radio button behavior)
- **All** selected by default
- Clicking a selected pill does nothing (stays selected)
- Clicking a different pill selects it and unselects the previous one
- Pill selection determines:
  1. Which API endpoint is called
  2. Which sections are displayed

### Pill-to-Endpoint Mapping
| Selected Pill | API Call | Sections Shown |
|---------------|----------|----------------|
| All | `GET /search/{query}` | Songs, Artists, Albums |
| Songs | `GET /search/{query}/songs` | Songs only |
| Albums | `GET /search/{query}/albums` | Albums only |
| Artists | `GET /search/{query}/artists` | Artists only |

### Component Details

#### Search Bar
- Large input: "Search for songs, albums, artists..."
- Green submit button
- Triggers on Enter key or button click
- Disabled during loading

#### Song Card
- **Layout**: Horizontal card
- **Left**: Album icon (iconURL) - square
- **Center**: 
  - Song name (white, medium font, not bold)
  - Artist names (small grey font, comma-separated)
- **Right**: Green download icon button (aligned with icon height)
- **Behavior**: Download button greys out for 30 seconds after click

#### Artist Card
- **Layout**: Vertical card in horizontal scroll
- **Icon**: Large circular image (iconUrl)
- **Name**: Below icon, medium white font
- **Label**: "Artist" text below name, small grey font
- **Behavior**: Display only (no interaction)

#### Album Card
- **Layout**: Vertical card in horizontal scroll
- **Icon**: Large square image (iconURL)
- **Name**: Below icon, medium white font
- **Artist**: Below name, small grey font
- **Year**: Below artist, small grey font
- **Behavior**: Display only (no interaction)

### Empty/Loading States
- **No search yet**: Empty state with prompt
- **Loading**: "Searching..." text or spinner
- **No results**: "No results found for '{query}'"
- **Empty section**: Hide section if no results for that type

### Image Fallbacks
- Missing/failed images show grey placeholder

## 5. State Management

### App Component State
```typescript
const [query, setQuery] = useState<string>('')
const [results, setResults] = useState<SearchResponse | null>(null)
const [loading, setLoading] = useState<boolean>(false)
const [selectedPill, setSelectedPill] = useState<'all' | 'songs' | 'albums' | 'artists'>('all')
const [downloadingIds, setDownloadingIds] = useState<Set<string>>(new Set())
```

### Download Cooldown Logic
1. User clicks download button for song with `id`
2. Call `download(id)` API
3. Add `id` to `downloadingIds` set
4. Button becomes grey/disabled
5. After 30 seconds, remove `id` from `downloadingIds`
6. Button becomes active again

### Artist Name Resolution
Since songs and albums have `artists: string[]` (artist IDs), we need to resolve these to names:

```typescript
function getArtistNames(artistIds: string[], artists: Artist[]): string[] {
  const artistMap = new Map(artists.map(a => [a.id, a.name]))
  return artistIds.map(id => artistMap.get(id) || 'Unknown Artist')
}
```

Display as comma-separated: "Artist1, Artist2, Artist3"

### Production Build

### Dockerfile
```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
RUN npm install -g serve
EXPOSE 3000
CMD ["serve", "-s", "dist", "-l", "3000"]
```

### docker-compose.yml
```yaml
version: '3.8'

services:
  frontend:
    build: .
    ports:
      - "3000:3000"
    environment:
      - VITE_API_URL=${API_URL:-http://localhost:8080}
```

### Deployment
```bash
docker-compose up --build
# Access: http://localhost:3000
```

**Note**: Client and server assumed to be on same local network. No Nginx needed.
